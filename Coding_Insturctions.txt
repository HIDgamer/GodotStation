Coding Instructions for UACMGS

This Project is ran on the latest Godot version 4.X

Formatting Standards

Use tab characters for indentation at all times. Do not use spaces.

Begin comments with (#) in GDscripts or (//) for C# scripts and ensure they clearly describe the purpose or behavior of a method, block, or script.

Avoid redundant or obvious comments. Every comment must add clarity or context.

Resource and Scene Referencing

Do not use preload(). All resources and assets must be loaded using load().

When referencing files, scenes, scripts, or assets, always use the UID-based path rather than direct file system paths. This prevents broken references caused by file moves or renames.

Godot-Specific Coding Requirements

All Node lookups must be performed using get_node() or get_node_or_null() with absolute or well-structured relative paths. Avoid hardcoding deep or fragile node paths.

Avoid calling get_tree().get_root() unless necessary. Prefer passing node references explicitly.

Do not use autoloads as global storage unless the data truly must be globally accessible. Favor dependency injection through the scene tree where possible.

Avoid heavy logic inside _process() or _physics_process() unless required. Prefer event-driven or signal-based approaches to reduce frame-dependent complexity.

Use signals instead of polling to handle state changes or interactions where appropriate.

Do not instantiate scenes using new(). Always use instantiate() on PackedScenes to ensure proper initialization.

Free nodes using queue_free() instead of free() to avoid mid-frame deletion issues.

For multiplayer logic, do not rely on direct RPC calls inside gameplay scripts without authority checks. Always validate: "Is this node the authority?" before performing state-changing actions.

Keep scripts modular. A script should only handle the responsibilities directly related to the node it is attached to.

Avoid deeply nested logic in a single method. Break long functions into smaller, clear, single-purpose methods.

Performance and Memory Practices

Avoid unnecessary allocations inside the main loop. Reuse objects where possible, especially in frequently called code.

Use typed GDScript (static typing) for every variable, argument, and return type to improve performance and catch errors early.

When using TileMaps, cache layer references and avoid calling expensive TileMap API functions repeatedly inside loops.

For large maps, chunk TileMaps into separate scenes or TileMap layers loaded/unloaded dynamically. Do not place the entire world in a single TileMap.

Always profile performance when implementing systems that may run every frame or scale with map size, entity count, or AI count.

File and Scene Organization

Every script must have a single clear purpose documented at the top using a short summary comment.

Keep file and scene names consistent, descriptive, and aligned with their function.

Place reusable code in separate utility scripts or classes. Do not duplicate logic across multiple scripts.

Maintain a strict folder hierarchy for scenes, scripts, assets, and data to ensure predictable navigation.
